## 8. Where a guard could sit (facts only)

- **(a) Pi forwarder** (`local-serial-log-forwarder` e27bce8, `src/serial_reader.py`):
  - One `write_log` per non-empty line (:96-103). Each appends to `/var/log/serial-forwarder/<name>.log` and makes one synchronous POST (:61-70).
  - The POST (:22-58) has a 3 s timeout and no retry; a non-2xx or exception is printed and the line dropped (:51-58). One thread per device (:142-145).
  - No batching, rate limit or dedupe anywhere in the 148-line file. The synchronous POST is the only limiter today, at about 1.1 lines/s per device. The local file write is unbounded in code; Pi disk use was not measured.
- **(b) Ingestion Lambda serial path** (`lambda/src/ingestion.ts`):
  - Auth (:57), S3 key (:113), S3 put (:129), log-events put (:137), current-state get (:156), update (:161), ledger refresh (:174), event-history (:219), then 200 (:258).
  - No per-device rate check or dedupe. Every line costs 1 S3 PUT, 1 log-events write, 1 current-state read and write, a ledger step, and conditional history writes.
- **(c) API Gateway usage plan, serial key:**
  - Plan `t3oq8d` (particle-ingestion-serial-forwarder): rate 10/s, burst 50, no quota. Per key, and that key is shared by every serial device behind the forwarder.
  - Aggregate on key 2eisotew77: flood peak second 3 req, peak minute 77; baseline peak second 4 req, peak minute 74 (Oct 3 10:22).
  - The current limits were never approached. A per-key limit tight enough to stop this flood would have returned 429 to normal multi-device boot bursts, and the forwarder drops a line on 429 ((a) :51-55).

## Summary for placement and thresholds

- **Placement:** the shared-key usage plan can't separate this flood from normal traffic (peak minute 77 versus 74); the flood is only distinct per device. The forwarder (a) and the Lambda (b) both see the device ID, and today the forwarder alone sets the ceiling, which also hides the device's true rate.
- **Threshold range (from 7):** single minutes reach 54 normally, leaving little margin under the about 66/min ceiling. Sustained measures separate cleanly: a 5-minute total between about 100 (baseline max 94) and about 300 (flood 333), or more than 30/min for 2–3 or more consecutive minutes (baseline max run 1, flood 10).
- **Not measurable:** the device's true emission rate and lines lost before the forwarder; Pi local log growth; which code runs on the Pi; table sizes before the flood; per-request API Gateway latency and request ID (the access-log format has no latency, and the Lambda doesn't log API Gateway's request ID); exact dollar cost (list prices are approximate).
